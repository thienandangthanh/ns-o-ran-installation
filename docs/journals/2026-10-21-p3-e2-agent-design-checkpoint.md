## 2. What is fixed by the contract (not up for decision here)

- Approach A: one out-of-process agent per E2 node, each in its own network namespace, built with NIST's e2-interface build at `da6f82f2`.
- Agents connect to the e2term **Service**, never to a pod IP.
- ns-3 links no asn1c or e2sim.
- Subscription option A now: accept, then forward every sample. Option B later must change only the agent.
- Every IPC sample carries the full metric set plus the sim timestamp.
- kpimon gets only the SIZE(8) patch.
- M5–M7 run free (no pacing). RC/M8 is deferred, but nothing may preclude it.
- D3: `--nMmWaveEnbNodes` (default 4).

## 3. Why NIST's e2sim main loop cannot be the agent

These were read in the pinned source and decide the agent's shape (citations in the counsel, Q3):

- `run_loop` `exit(1)`s when the connect fails, hard-codes `OID123`, and blocks in its receive loop.
- Subscriptions are dispatched synchronously to a plain callback. NIST's kpm_sim then runs its report loop **inside** that callback and never reads SCTP again. It cannot answer a second subscription, a delete or a service query.
- Subscription **delete** is never dispatched at all.
- The library's send and receive paths `exit(1)` on −1 and send without `MSG_NOSIGNAL`.
- The E2AP generators have bugs:
  - the subscription response hard-codes `RANfunctionID = 147`;
  - the "not admitted" branch writes into the admitted IE;
  - the indication generator copies into a fixed 8192-byte buffer.
- Identity is hard-coded: gNB-ID `B5C67788`, PLMN `747` (`encode_e2apv1.cpp:158-174`). So every agent would be the same node.

## 4. Recommended design

### 4.1 Agent shape (Q3)

- A small C++ agent owns **one single-threaded `poll()` loop** over these file descriptors:
  - the SCTP socket to e2term;
  - the IPC listen socket and client socket;
  - a timer.
- It **reuses NIST's code unmodified**: libe2sim's E2AP generators (setup request, subscription response, indication, service update) and the asn1c codecs for E2AP and E2SM-KPM v3.
- It does **not** use `run_loop`, the callbacks, `sctp_start_client` or the global `client_fd`.
- Identity (gNB-ID, PLMN), the KPM OID, and the generator bugs (RANfunctionID 147, the not-admitted branch, message size) are fixed by **editing the generated PDU in place** before encoding.
- The agent writes its own encoders: a subscription-delete response and the E2SM-KPM pieces (RAN function description, header, message formats 1 and 2).
- **Result: none of NIST's e2sim or kpm_sim files is changed**, and NIST's own kpm_sim image builds exactly as before.

### 4.2 Source home and build (Q3)

- Source lives on the Testbed fork in a new directory, `RAN_Intelligent_Controllers/Near-Real-Time-RIC/ns3_e2_agent/`:
  - `src/` — one concern per file;
  - `schema/` — `ns3-e2-ipc.v1`, `metric-map.v1.json`;
  - `tests/codec-probe.cpp`;
  - `install_scripts/` — install, run and stop.
- The Dockerfile is derived from NIST's `Dockerfile_kpm`, built in the e2-interface tree at `da6f82f2` right after NIST's `install_e2sim.sh`. Changes from NIST's file:
  - nlohmann-json comes from apt, not an unpinned `git clone`;
  - the agent is the ENTRYPOINT, so Docker's restart policy sees its exits.
- The `oran-e2sim` (wineslab) fork branch `dev/l-release-nist180` stays as cut from the pin and **unused**, as the contract allows.

### 4.3 Placement and transport (Q2)

- **Container per agent.** One Docker container per E2 node on the default bridge, with its own netns:
  `docker run -d --init --restart always --label ns3e2.agent=1 --label ns3e2.nodeId=<id> -p 127.0.0.1:<38470+id>:<38470+id> ns3-e2-agent:<sha>`.
- This is the exact path the M2 probe proved.
- **Why not k8s pods:** the image would need a containerd import, pod IPs change, CrashLoopBackOff tops out at 5 min, and the path is unprobed.
- **ns-3 → agent:** TCP to `127.0.0.1:(38470 + cellId)`. These are the same numbers ns-3 used as local SCTP ports.
- **Agent → e2term:** the host resolves the e2term SCTP Service's **ClusterIP** at agent start, using NIST's selector and asserting exactly one Service. It passes the ClusterIP as `E2_TERM_ADDR`. Containers cannot resolve cluster DNS.
- The ClusterIP survives e2term pod deletes, so M7 needs no IP change.

### 4.4 IPC (Q1)

**Transport and framing.** Newline-delimited JSON over TCP (`ns3-e2-ipc` v1):
- **hello**: schema, version, nodeId, kind, period, simStartEpochMs, runId, and the emitter SHAs.
- **sample**: one per node per period, with DU, CU-UP and CU-CP merged.
  - Node fields: `nodeId`, `seq`, `simTimeNs` (int64) and `ipcDropped`.
  - `cell{du,cuUp,cuCp}`.
  - `ues[]`, sorted by IMSI, with DU, CU-UP and CU-CP values plus L3 serving and neighbour SINR.
- **bye**: final counters.

**Why JSON over the alternatives:**
- The NIST build image already ships nlohmann-json, and kpm_sim already reads line-delimited JSON.
- ns-3 needs only about 100 lines of serializer, and no new library.
- Shortest-round-trip doubles make the M6 comparison **bit-exact**.
- The trace file ns-3 writes is byte-for-byte the wire. It is the M6 ground truth.
- Protobuf would add codegen in two toolchains, and CBOR gains nothing.

**Full-set rule.** The sample carries every value ns-3 computes, from both the ASN.1 branch and the file-logging branch, regardless of `reducedPmValues`. Option B can then filter in the agent alone.

**Reserved for M8.** The `control`, `controlAck` and `step` message types; v1 emitters drain and ignore inbound bytes.

### 4.5 E2SM content (Q4), checked against kpimon's code

**RAN function:**
- ID **2**. kpimon subscribes with funcId 2, requires the node to advertise it, and hard-codes 2 in its action encoders. ns-3's old 200 is retired.
- Short name **`ORAN-E2SM-KPM`**. Wireshark selects the KPM dissector by this exact string; ns-3's old `ORAN-WG3-KPM` would never decode.
- OID **`1.3.6.1.4.1.53148.1.3.2.2`**, the real KPM v3 OID. Nothing on the RIC side is known to check it. If e2term rejects it at M5, fall back to `E2_KPM_OID=OID123`.

**Report styles in the definition: two.**
- Style 1: action format 1 → message format 1, with the **cell** measurement list.
- Style 3: action format 3 → message format 2, with the **UE** list.

kpimon builds its single action from these lists.

**Header:**
- Format 1, with an 8-byte `colletStartTime` in NTP-64 form: seconds since 1900 plus fraction, computed from `simStartEpochMs` + sim time.
- kpimon decodes the header and discards its fields; Influx stamps `time.Now()`.

**Messages**, both under kpimon's single subscription; kpimon dispatches by message format, not by action:
- **Cell metrics: Format 1.**
  - Records follow exactly the order of the advertised cell list, with `noValue` where a value is missing.
  - kpimon drops the whole message if the record count differs from the list length.
  - Result: one `cellMetrics` point per sample.
- **Per-UE metrics: Format 2**, metric-major.
  - The list is ordered metric by metric, then UE by UE in IMSI order, as kpimon's parser expects.
  - Result: one `UeMetrics` point per UE.

**Value types:**
- kpimon casts INTEGER to int32. So INTEGER is used only for values that stay in 0..2^31−1: IDs, bounded per-period counts, percentages.
- Volumes, bytes, throughput, delay and SINR in dB are **REAL**. An out-of-range INTEGER becomes `noValue` and is counted.

**Correlation without kpimon tags (K2).** Both lists start with `ns3.nodeId`, `ns3.simTimeMs` and `ns3.seq`; the UE list adds `ns3.imsi`. M6 and M7 join Influx rows to the ns-3 trace on `(nodeId, seq)` and `(nodeId, seq, imsi)`, never on `_time`.

**Wire compatibility.** The agent encodes with NIST's KPM v3 asn1c; kpimon decodes with v2 plus SIZE(8). The structures used are identical between the two. Rule: never set a v3 extension field.

**Size.** At most 4 UEs per indication, and the chunk is halved if the E2SM message exceeds 7000 bytes. This keeps clear of the generator's 8192-byte buffer.

### 4.6 Metric map (Q5, K5)

- One versioned file, `ns3_e2_agent/schema/metric-map.v1.json`.
- Each row maps an ns-3 field (JSON pointer into the sample) to a KPM measName, list, order, measID, type and unit.
- The agent logs the file's sha256 and puts its sha8 in the RAN function description.
- The M6 gate reads the **same file** at the pinned SHA and asserts the sha matches.
- **Names must be PrintableString-legal.** `_` is not allowed, so `_Filter` and `.UEID` are dropped from the names.
- **Collisions.** A DU/CU-UP name collision gets an `ns3.du.` prefix. Values without a 3GPP name become `ns3.<section>.<field>`.
- **L3 measurements.** The legacy `valueRRC` items (L3 serving and neighbour SINR) are flattened into numeric `ns3.l3.*` columns. KPM records carry only integer, real or noValue.
- **Gate lint:** one type per name; legal characters only; no overlap with kpm_sim's 9 names; stable, unique measIDs.

### 4.7 Robustness (Q6, K7)

**Agent state machine:**
1. **HOLDOFF**, 8 s.
2. **CONNECTING**: a fresh socket on an **ephemeral source port**, retried every 2 s, forever.
3. **SETUP_SENT**: no response within 10 s means `exit(3)`.
4. **READY**: the subscription table starts empty. Then:
   - a subscription request for function 2 → admit all actions and store them;
   - a subscription delete → remove the entry and reply;
   - a service query → reply with a service update;
   - an undecodable PDU → log and count, never exit.
5. **Association lost** → `exit(2)`. Docker restarts the container, which comes back with empty state and goes through HOLDOFF to a fresh E2Setup.

**Why 8 s:** kpimon re-subscribes only after one of its 5 s polls sees the node not CONNECTED. A faster return leaves the node "CONNECTED but silent".

**Why an ephemeral port:** a reconnect from the same NAT 5-tuple can be DNAT'd to the dead pod's conntrack entry. A new port means a new flow. NIST's kpm_sim keeps 36422; the M2 probe showed both work for a first connect.

**The agent never exits because it cannot connect yet.** Otherwise Docker's restart backoff grows to 60 s.

**ns-3 emitter:**
- Non-blocking TCP; every send uses `MSG_NOSIGNAL|MSG_DONTWAIT`.
- A bounded buffer; on overflow, drop and count.
- Reconnect with backoff from 0.1 s to 5 s; send `hello` on every connect.
- Write the trace line before sending, so the trace also records dropped samples.
- Scheduled at init, as file-logging mode does. ns-3 never waits for a subscription and never stalls sim time.

**What M7's e2term pod delete should show on `docker0`, per node:**
1. The association ends.
2. The container restarts.
3. About 8 s later, a new INIT from a new port.
4. E2Setup with function 2 accepted.
5. A **new** RICsubscriptionRequest from kpimon within about 5 s.
6. Indications resume.

### 4.8 Lifecycle and node sets (Q7, K11)

| Config | E2 nodes (cellId) | Agents | IPC ports |
|---|---|---|---|
| default (`e2lteEnabled` true, 4 mmWave) | eNB 1 + gNB 2–5 | 5 | 38471–38475 |
| `--nMmWaveEnbNodes=1` | eNB 1 + gNB 2 | 2 | 38471–38472 |
| P5 single node: `--nMmWaveEnbNodes=1 --e2lteEnabled=false` | gNB 2 | 1 | 38472 |

- **Node set.** One shared node-set function, used by both the agent launcher and the ns-3 launcher, derives this table. M4 asserts the cellIds from ns-3's `hello` lines rather than trusting the derivation.
- **Names.** e2mgr names nodes `gnb_001_001_0000000N` (PLMN 001/01, gNB-ID = cellId). These differ from kpm_sim's.
- **Discovery.** Gates find agents through Docker labels plus `run/agents.json`, and each agent writes a stats line every 5 s.
- **Capture.** On `docker0` with BPF `ip proto 132`, started **before** the agents, because Wireshark learns the E2SM mapping only from E2Setup.

## 5. Decisions that need your sign-off

**S1. Reverse K1's mechanism (outcome-neutral, approach detail).** The review recommended option (a), patching NIST's `encode_e2apv1.cpp`/`e2sim.cpp` to read identity from env vars. This design uses option (b) instead: the agent owns its loop and edits the generated PDUs, and **no NIST file is modified**.
- Reason: section 3. Patching the library cannot fix the blocking callback, the missing delete dispatch or the `exit(1)` paths. It would also rebuild NIST's own kpm_sim from patched code.
- Trade-off: about 1–1.5k lines of agent-owned C++ (state machine, KPM encoders, delete response), each file under 200 lines.
- **Recommend: yes.**

**S2. The LTE eNB registers as a gNB-type E2 node.** scenario-zero's LTE eNB (cellId 1) is an E2 node by default. NIST's setup generator builds only gNB identities.
- Options:
  - (a) Register it with a gNB-type GlobalE2node-ID: distinct ID, e2mgr name `gnb_001_001_00000001`. It still reports its eNB metric set (CU-UP/CU-CP).
  - (b) The agent writes an eNB-type GlobalE2node-ID builder. This adds code, and kpimon's and e2mgr's handling of eNB-type nodes is unprobed.
  - (c) Exclude the LTE eNB from E2 by setting `--e2lteEnabled=false` everywhere. This changes the default node set, so "every scenario-zero E2 node" would no longer include it.
- **Recommend: (a)**, labelled honestly in the evidence and docs.

**S3. P5's "single gNB" uses `--nMmWaveEnbNodes=1 --e2lteEnabled=false`.** D3's flag alone still leaves the LTE eNB, so 2 E2 nodes. `--e2lteEnabled` is an existing CLI option, so this is a configuration choice, not a code change. M7 runs the default set (5 nodes).
- **Recommend: yes.**

**S4. Reconnect behaviour: an 8 s hold-off and an ephemeral SCTP source port** (section 4.7).
- This is inside the contract (robustness detail), but it differs from NIST's fixed 36422 and from the plan text "agent restart is enough".
- **Recommend: yes.** M7 records time-to-reconnect, and a run with port 36422 is kept as an informational comparison.

Also recorded, no decision needed:
- **Real KPM v3 OID**, with `OID123` as the fallback if M5 rejects it.
- **NTP-64 TimeStamp** instead of ms-since-epoch.
- **PLMN 001/01 BCD** instead of ns-3's ASCII "111". The old ns-3 identity was not valid BCD.
- **Metric names lose `_Filter`/`.UEID`** (PrintableString), with `metric-map.v1.json` as the authority.
- **M6 float comparison is bit-exact** (0 ULP), which is stricter than the plan's "documented rounding rule".

## 6. Risks and early probes (run right after sign-off, before P4 fixes types)

- **R1: codec paths no gate has exercised yet** — REAL records, Format 2 with UE IDs, the two-style definition. NIST's kpm_sim sends only Format 1 integers.
  - Probe, about 2 h, no RIC needed: in the agent image, encode the definition, a header, Format 1 (INT/REAL/noValue, extreme doubles) and Format 2 (3 metrics × 2 UEs). Decode them with kpimon's own library through the harness.
  - Pass when every piece is a clean RC_OK and the doubles are bit-identical.
  - If Format 2 UE IDs fail, the fallback is Format 2 without UE IDs. If REAL fails, STOP and ask, because it changes M6.
- **R2: nodes come back CONNECTED but silent after the e2term pod delete.**
  - Probe in P5 with one agent: `docker restart` it, delete the e2term pod, and record the timeline.
  - If it fails despite the hold-off, that is a Decision (a kpimon or RIC change is out of scope).
- **R3: size and rate limits** (generator buffer, RMR message size, kpimon one-goroutine-per-indication).
  - Probe with a replay tool: Format 2 messages of 1.5, 3 and 6 KB, and a 10× rate for 60 s. Compare Influx row rate with indications sent.

## 7. M3 results (kpimon)

Source: the green M3 run, `plans/261021-1823-GH-1-ns-oran-l-release-m0-m7/evidence/m3/20261021T141438Z`, independently re-counted with tshark. Numbers are from one 505-indication kpm_sim burst per phase.

| | stock kpimon (SIZE(4)) | patched kpimon (SIZE(8)) |
|---|---|---|
| wire indications (tshark, TSN-deduped) | 505 | 505 |
| harness header (kpimon's own `.so`) | RC_WMORE 505 | **clean RC_OK 505** (consumed = length, TimeStamp 8 octets) |
| harness message | RC_OK 505 | **clean RC_OK 505** |
| kpimon log `header RC_WMORE` | 505 | **0** |
| kpimon log indications received | 505 | 505 |
| Influx `kpimon` values written | yes | 2970 |

What this tells P5:
- **The SIZE(8) patch is necessary and sufficient for clean header decoding of an 8-byte TimeStamp.** NIST's own reference node fails without it, as erratum 1 predicted.
- **The 8-byte TimeStamp on the wire is NIST's ASCII "20200613".** kpimon discards header fields, so the agent's NTP-64 value is equally acceptable.
- **kpm_sim sends a finite burst** of about 505 indications in about 25 s, then stays silent. It is no load generator; ns-3 will be the steady source.
- **The kpimon log count matched the wire exactly (505/505) in the green run.** Two earlier attempts showed 9–13 unlogged indications during the burst, so M6 re-measures this at ns-3's rate.
- **`UeMetrics` stays empty with kpm_sim**, because kpm_sim sends only Format 1. As the counsel predicts, the agent's Format 2 path is first exercised by the R1 probe.
