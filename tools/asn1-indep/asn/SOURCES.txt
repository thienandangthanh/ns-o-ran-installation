Compile edits (applied by compile-asn.py to a temporary copy; each must match once)
-----------------------------------------------------------------------------------
1. e2ap-pdu-v03.01.asn: add `RICtimeToWait,` to the IMPORTS from E2AP-IEs.
   E2AP-PDU-Contents uses RICtimeToWait (RICaction-RequiredToBeModified-Item) but
   does not import it; pycrate stops at the undefined reference. Import list
   only, no type changes.
2. e2ap-epd-v03.01.asn: IMPORTS `RICqueryRequest, RICqueryResponse, RICqueryFailure`
   -> `RICQueryRequest, RICQueryResponse, RICQueryFailure`. E2AP-PDU-Contents
   defines RICQuery* and the elementary procedure set references RICQuery*; the
   import list had the wrong case. Type names are not encoded, so no wire change.
3. e2sm-rc-2.0.asn: `RANParameter-ID ::= INTEGER (1..2^32, ...)` ->
   `INTEGER (1..4294967295, ...)`. `2^32` is not ASN.1 value notation; the edit
   writes the bound O-RAN E2SM-RC v03.00 states in its own ASN.1 (Zotero
   JRDTL7XS, p. 287). (2^32 written in decimal would encode identically:
   pycrate sizes the length determinant from range - 1, 4 octets either way.)
   Finding: the asn1c code generated from this same file (rc@a2282ee
   e2sm/lib/RANParameter-ID.c) has `APC_UNCONSTRAINED` for value and size, i.e.
   asn1c dropped the constraint. asn1c puts RANParameter-ID on the wire as an
   unconstrained INTEGER (no extension bit, length octet, value), X.691 as an
   extensible constrained INTEGER (extension bit, 2-bit length, value - 1). The
   asn1c-encoded RC control messages of tools/rc-decode/fixtures therefore do not
   decode with this codec; selftest.py pins the exact difference.
