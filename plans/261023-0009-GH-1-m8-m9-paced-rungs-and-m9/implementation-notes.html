P0: harness generalization, RC wire decoder, disk baseline

  • decisionGate id = ^gate-([a-z]+[0-9]+) through one gate_id helper in vm-common.sh, used by vm-exec.sh and self-tested in lint.sh (m5 r0 s1 q7).
  • decisionProtected snapshots live in one list, VM_NEVER_DELETE=(fresh-install f7-rerun-green r3-green); vm-snapshot.sh delete refuses them before any virsh call and check-protected exposes the rule.
  • decisionThe disk watchdog keeps the minimum free space seen in min-host-free-gb.txt, so the M9 verdict reports minHostFreeGb from the watchdog, not from point samples. On a trip it kills the runner's foreground child first: bash defers a TERM trap until the foreground child exits, and a stopped VM unit never writes exit_code, so vm-exec.sh would otherwise wait ~20 min for ssh.
  • decisionrun-to-m9.sh step names: i0 (decoder + rc install), r0, r1, i2 (TS xApp + stub QP), r2, i3 (stub down + QP fork), r3. Install steps are gates of their own so each has a verdict and evidence. The runner writes evidence/m9/<ts>/verdict.json on every exit path.
  • decisionRC decoder tools/rc-decode/: asn1c mouse07410@584d86e (−O0) over rc@a2282ee e2sm-common.asn + e2sm-rc-2.0.asn, APER, XER out. "ok" = RC_OK and every octet consumed (the M0–M7 decoder rule). It never calls asn_check_constraints (loops on RANParameter-bearing PDUs).
  • decisionFixture: 30 RICcontrolRequest PDUs from the probe pcap (sha256 e57c5713…), tshark 4.7.4 fields e2ap.RICcontrolHeader/e2ap.RICcontrolMessage. Every header decodes 22/22 octets with style 3, action 1, UEID = gNB-UEID; every message 36/36 octets with the NR CGI as valueOctS of RAN parameter 4 nested under parameters 1/2/3. A synthesized ControlOutcome Format 1 with an empty ranP-List encodes to 0000 and round-trips.
  • decisionThe probe's NR CGI octet string is 9 bytes (00 00F110 0000000003). It is raw octets, not APER: rc a2282ee builds it as hex.DecodeString("00"+PLMN+TargetCellID) (control/rcE2SmRc.go:101-102; the APER NR-CGI encoder in e2sm/wrapper.c is commented out). The agent parses length 9, byte 0 = 00, bytes 1–3 = PLMN, bytes 4–8 = the 5-byte cell key; with the N5 key %08X%02X the target cell id is byte 8. An APER NR-CGI decode would drop that byte (it sits in NCI's pad nibble, verifier-1723 #12) and give NCI 0. (Corrected 02:02 KST after kongming's P0 exit review; an earlier note here said APER.)

  • decisionStale-build guard: agents_ns3_locate reuses ~/m4-build only when its ns-3 and oran-interface HEADs equal pins.conf, else rebuilds, and writes ns3-binary-provenance.txt. agents_install_image reuses an image only when its tag is ns3-e2-agent:<short12 of the Testbed HEAD> (the installer's tag) and the map sha matches.   • decisionns-3 trace text files (**/ns3run/*.txt, up to ~50 MB each, 1.5 GB over M0–M7) are gitignored in this plan's evidence; vm-exec.sh writes ns3run-sha256.txt next to pcap-sha256.txt. IPC traces (*.jsonl) stay committed. Confirm with the user at Stop A.
  • decisionD4 precheck "already on target" = not on the LTE stack and m_lastMmWaveCell == target: the outage switch leaves m_lastMmWaveCell unchanged (lte-enb-rrc.cc:4762-4768), so without this a UE on LTE fallback would be mislabelled. K5's order is kept.
  • decisionControl path in oran-interface (it links only libcore, so it cannot call LteEnbRrc): E2ControlHub buffers the control lines every emitter drains; when the last registered emitter has emitted seq k it drains all emitters once more and applies the buffer synchronously at that sim time (d = 0) in C4 order through a callback the LTE master device registers. One ledger line (e2-control-ledger.jsonl, header delta-model fixed 0, fields rxSeq, rxSimTimeNs, applySimTimeNs, viaNodeId, ctlId, afterSeq, imsi, sourceCell, targetCell, outcome, cause) and one controlAck per control. Controls buffered or arriving at stop: refused/late. No control: no file, no event, no state change. This is P2's barrier point in free mode.
  • deviationCommit order differs from the phase file (sequence only, kongming R6): the ledger writer lives in the oran-interface commit (with the hub), not an ns-3 commit B; ns-3 commit B only registers the handler and adds --e2LedgerPath. V1 is run at every pinned (ns-3, oran-interface) pair: commit A with the P0 oran-interface, and the final pins.
  • decisionAgent RC codec = rc a2282ee's own generated E2SM-RC code (asn1c 0.9.29, the code rc encodes with), built into librc_codec.so with hidden visibility and a separate include path, exporting only rcc_*. It cannot clash with NIST's E2AP/KPM asn1c, and it is a different generator from the gate decoder (tools/rc-decode, asn1c 584d86e), so a generator bug cannot pass both.
  • decisionAgent answers: RAN function ≠ 3 → ran-function-id-invalid; E2SM decode error or target octets not 00|PLMN|key (9 octets) → control-message-invalid; style/action ≠ 3/1 → action-not-supported; ns-3 not connected or the IPC send fails → control-failed-to-execute (agent-local, counted rejIpcDown); ns-3 refused, late, or bye/EOF with the control pending → control-failed-to-execute; applied → ACK with Outcome Format 1 0000. An ACK that cannot be built becomes a FAILURE, so every request has exactly one terminal answer.
  • decisionRIC Control Ack Request = NoAck and applied → no message (E2AP v03.00 §8.2.4.2). rc a2282ee never sends that IE (probe pcap: IEs 29, 5, 22, 23 only), so this changes nothing on the wire today; it keeps the agent spec-faithful.
  • questionThe agents accept RAN function 3 without announcing it in E2 Setup (they announce only KPM, function 2). E2AP v03.00 §8.2.4.3 says a control for a function not announced gets a FAILURE. The locked design rejects only functions ≠ 3, which the user approved with this known (probe side finding 2026-10-22). Raised at Stop A; not a new deviation introduced here.
  • decisionLocal dev runs (host container, Ubuntu 24.04 toolchain, not gate evidence): at RngRun 1 with the default −5 dB threshold, 4 of 6 UEs switch to LTE within 2 s and never return under NoAuto, so most controls get lteFallback. This is the Q2 question P3 settles with its null-control count (substitution 1). With −1000 two controls applied, and HandoverStart followed 3 ms after the apply time.
  • decisionAgent unit test expectation fixed after a first local run: the probe numbered its 30 calls, so fixture line k carries AMF-UE-NGAP-ID k+1 (the independent decoder agrees); the first draft expected 1 on every line. The final check is stricter than the draft, not looser.
