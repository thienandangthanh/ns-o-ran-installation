TS case-insensitive cell-prefix grep: normalise both sides to lowercase

The plan only said “case-insensitive grep.” I chose to lowercase the whole decoded message and the ranName-derived prefix, rather than uppercasing. Keeps cell_map keys in E2MGR’s natural-looking lowercase and is robust whichever case E2MGR emits. (Turned out E2MGR renders the requestPart UPPERCASE — see Deviations — so this normalisation is genuinely load-bearing, not cosmetic.)

2026-06-14 20:06 KST

requestPart bytes = [gNB-id 4B ++ cellByte] per served cell

Reverse-engineered from TS’s NodebHandler: it greps the (hex-rendered) requestPart for the 8-hex gNB-id prefix and grabs substr(i,10) — i.e. prefix(8) + one extra byte (2 hex). So one trailing cell byte per entry is exactly what TS needs; rc later decodes the NRCGI’s last byte = that cell. Compact testbed convention, not a full O-RAN NRCGI (see Open questions).

2026-06-14 20:05 KST

gNB-id value = 0x16B8CE00 | cellId, bits_unused=0 (32-bit)

Needed a unique id per gNB (else E2MGR coalesces them) with a stable hex width (else leading-zero stripping breaks TS’s fixed-length prefix grep). Keeping the top nibble = 1 (the 0x16… base) guarantees E2MGR always renders 8 nibbles, and the low byte = cellId gives uniqueness + a recognisable family. Switched bits_unused 3→0 so the rendered value maps 1:1 to the bytes.

Tradeoffs alternatives weighed

2026-06-14 20:18 KST

Case fix: lowercase-both vs remove-toupper vs uppercase-both

Three viable fixes. “Remove toupper” is smallest but assumes ranName is lowercase. “Uppercase-both” yields uppercase keys (less natural, must match mock JSON). Chose lowercase-both: robust to either side’s case and keeps keys lowercase like a real kpimon-fed key would look.

2026-06-14 20:08 KST

gNB-id low byte = cellId (≤255 cells) vs a wider field

Encoding the cellId in the last byte caps unique gNBs at 255 and keeps the prefix at a clean 8 nibbles. A wider field (2+ bytes) would lift the cap but complicates TS’s substr(i,10) math. Picked the KISS path — testbed scenarios are far below 255 cells.

2026-06-14 20:05 KST

Default args on the encoder vs hard-required params

Gave the two new encoder params defaults (0x16B8CEF1, empty cells). Costs a tiny ambiguity but means any caller I didn’t find (examples/tests) still compiles and behaves as before. Single real caller passes explicit values.
