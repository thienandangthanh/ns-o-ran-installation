Date 2026-11-06 (KST). Advisory only. Runtime: Claude Code, Opus 5.5 (`model: opus`, per the user's CLAUDE.md override of the fable routing).

## TL;DR
Take **(b)**. Its numbers are correct: X2 `NRARFCN` (Point A) = **632758**, implied carrier reference F_REF = **633334** (3500.010 MHz, on the n78 30 kHz raster), MTC `carrierFreq` = **633312** (GSCN 7846, 3499.68 MHz), offsetToCarrier 0, `nR-TxBW` {scs60, nrb24} unchanged. **(a) is wrong, not just a different mapping.** Its implied carrier sits at F_REF 633909, which is off the 30 kHz raster. No offsetToCarrier can repair that, because Point A 633333 has odd parity. **(c)** breaks "fix to spec" for a fix that costs only constants, fixtures and one gate predicate, with no runtime effect. Land it in P10 as its own commit, first in the commit order. Register ledger row 143 (predicate) and row 144 (regenerated byte fixtures) before the code. The AC6a probe must be fixed in the same commit, because it repeats the same off-raster value and also sends a 30 kHz / 106 RB cell.

## 2. Arithmetic
- **Point A has no half-subcarrier term.** 38.211 §4.4.4.3: "The center of subcarrier 0 of common resource block 0 for subcarrier spacing configuration μ coincides with 'point A'". This holds for every μ. 38.211 §4.4.2: "The frequency location of a subcarrier refers to the center frequency of that subcarrier." Subcarrier n of the 60 kHz grid is therefore at Point A + n × 60 kHz, which is n × 4 NR-ARFCN steps.
- **The channel raster maps to a resource element as follows.** 38.101-1 Table 5.4.2.2-1 (p84) and 38.104 Table 5.4.2.2-1: with N_RB = 24 (even), k = 0 and n_PRB = ⌊24/2⌋ = 12. So F_REF = lowest carrier subcarrier + 144 × 60 kHz = +8.64 MHz = +576 steps. N_RB = 24 for 20 MHz at 60 kHz (38.101-1 Table 5.3.2-1, p66; 38.104 Table 5.3.2-1).
- **offsetToCarrier and k0 do not enter.** X2 carries no offsetToCarrier unless the optional NR Carrier List §9.2.168 (p309) is present, so the consistent reading is offsetToCarrier = 0. k0^μ (38.211 §5.3.1) is 0 when μ0 = μ, and here there is a single 60 kHz carrier.
- **(b) checks out.** 633334 − 576 = **632758**, which is 3491.370 MHz. 633334 is on the raster: 13334 is even and ≤ 653332. The carrier's subcarrier centres span 3491.370–3508.590 MHz. If the 20 MHz channel is centred on F_REF, the guard is 1.330 MHz low and 1.390 MHz high. The minimum is 1330 kHz (38.101-1 Table 5.3.3-1, p66), and its note formula, (BW − N_RB·12·SCS)/2 − SCS/2, is exactly this half-subcarrier asymmetry.
- **The (b) SSB is correct.** GSCN 7846 gives 3000 + 347 × 1.44 = **3499.68 MHz**, which is NR-ARFCN **633312** = 600000 + 347 × 96. It lies in n78's 7711–8051 range (38.101-1 Table 5.4.3.3-1, p91; 38.104 same). The SSB subcarrier centres run from 3496.080 to 3503.250 MHz, inside the carrier. The SSB's subcarrier 0 is 314 × 15 kHz above Point A, which gives N_CRB^SSB = 26 (in 15 kHz RBs) and k_SSB = 2. That matches Codex's offsetToPointA 26 / k_SSB 2. For an EN-DC PSCell, offsetToPointA is not signalled; k_SSB "is derived from the frequency difference between the SS/PBCH block and Point A" (38.211 §7.4.3.1).
- **No 60 kHz grid alignment is required.** 38.211 §7.4.3.1 says that for type A SSB, μ ∈ {0,1}, and k_SSB and N_CRB^SSB are expressed in 15 kHz units. The only extra constraint is that N_CRB^SSB coincides with a CRB of `subCarrierSpacingCommon`. For 30 kHz that means it must be even, and 26 is even. Every NR-ARFCN above 3 GHz is on the 15 kHz grid, so any GSCN is representable.
- **(a) is refuted.** F_REF = 633333 + 576 = 633909 (3508.635 MHz), and 13909 is odd, so it is off the 30 kHz raster. In general, any legal F_REF is even. The offset from F_REF back to Point A is also even: 576 steps, plus 48·offsetToCarrier for 60 kHz, and also even for a 30 kHz/51-RB numerology (612 + 24m). **So in this configuration Point A must be even, and 633333 can never be valid.** (a)'s SSB (633600, GSCN 7849) would sit inside the carrier, but that does not save it.
- **Mixed numerology is legal in n78.** 38.101-1 Table 5.3.5-1 (p72) allows 60 kHz at 20 MHz in n78. 38.101-1 §5.3.3 (p67) covers "multiple numerologies … multiplexed in the same symbol due to BS transmission of SSB". The §5.4.2.3 raster rule is written for exactly a carrier with SCS ≥ 30 kHz and a 30 kHz SSB. The limit applies only to SA: MIB `subCarrierSpacingCommon` allows only 15 or 30 kHz in FR1 (38.331 p548). A 60 kHz-only carrier cannot carry CORESET#0, which does not matter for an EN-DC PSCell.

## 3. Other fields in the served-cell IE
- **No X2 offsetToCarrier is needed.** The Carrier List IE is optional (`YES/ignore`). Adding it would mean new extension IEs in both codecs with no consumer, so do not add it.
- **nrb24 is consistent** with 20 MHz at 60 kHz (above) and with the new frequencies.
- **The MTC is consistent after the fix.** `ssbSubcarrierSpacing` kHz30 is correct for n78 Case C. There is no `ssb-ToMeasure` and no `physCellId`; both are optional, and so is the v1550 `campOnFirstSSB`. SMTC sf20/0/sf1: Case C at ≥ 1.88 GHz has 8 candidates, n = 0..3 (38.213 §4.1), which span about 2 ms. sf1 covers indexes 0–3, so it is self-consistent with a single SSB at index 0. Record "one SSB, index 0" as the project assumption; no change is needed.
- **Frequency Shift 7p5khz is correctly absent.** n78 is not in the Δshift band list (38.104 §5.4.2.1).
- **Predicted new octets.** I replicated `x2ap-codec-measurement-timing.c`, and the replica reproduces today's `1011353ea50000`. It predicts the MTC for 633312 as `1011353c050000`. NRARFCN goes from `09a9f5` to `09a7b6`; both are 3-octet APER, so the PDU length is unchanged. Regenerate these with pycrate and do not hand-patch them.
- **No new TS cell-map keys.** The TS xApp keys on every offset of the gNB-ID hex (`replay-ts-cell-map.py:12-16`). I scanned the predicted bytes for gNB IDs 2–86 and found no new or changed keys.

## 5. Identity layout: what else was checked
- **E-UTRA EARFCN 100/18100 is valid.** 36.101 Table 5.7.3-1 NOTE 1 (p207) and 36.104 NOTE 1 (p36) exclude the first 100 channel numbers for 20 MHz. 100 and 18100 are the first allowed, so the 20 MHz channel edge coincides with the band edge without crossing it. No action.
- **PCI = cellId is valid.** The NR range is 0..1007 and the E-UTRA range is 0..503 (both guarded at `e2-node-identity.cpp:105-112`), and every value is unique. PCI mod-3 planning is radio-planning practice, not conformance. No action.
- **TAC is fine.** The 2-octet Configured TAC `0001` with no 5GS-TAC matches 36.423 §9.2.110 (p280-281). Only the plan text has drifted.
- **AC6a probe: verified independently.** `e2-probe-node.py:149` passes no scs/nrb, so it inherits `scs="scs30", nrb="nrb106"` from `tools/asn1-indep/e2indep/x2ap.py:27`. That is a 40 MHz cell, and its Point A 633333 is equally off-raster. Fix it under row 143, as above.
- **ns-3 RB count: verified independently, from code.** `mmwave-phy-mac-common.cc:143-144` computes `ceil(bw / m_rbWidth)` with `m_rbWidth = 12 × 60 kHz` (`:135`), which gives 28 RBs = 20.16 MHz with no guard. This is a model abstraction, not a wire deviation. The wire's nrb24 is the 3GPP value for a 20 MHz channel, and nrb28 does not exist in the enumeration. Disclose it; do not change nrb24. Confidence is medium that the runtime value is 28: it assumes the `Numerology` attribute is applied before `Bandwidth`, which the declaration order supports.
- **Carrier centre.** 3500.010 MHz is the 30 kHz raster point nearest to ns-3's 3500 MHz. The other neighbour, 633332, is 3499.980 MHz.

## Assumptions
- X2 without a Carrier List implies offsetToCarrier = 0. Confidence: high. This is the only reading under which a single NRARFCN plus NRB places the carrier, and (b) is built on it.
- The SSB ARFCN means SS_REF, i.e. k = 120. Confidence: high for GSCN positions.
- The Zotero copies of 38.104, 38.211 and 38.213 match the archive versions I read. Confidence: medium. Re-check clause text and add pages before citing.
- The user rules "fix in M10". Confidence: medium. If the user instead rules "no non-T-C wire change after cp2", fall back to (c) with this report as the disclosure, but that contradicts the project's fix-to-spec rule.
