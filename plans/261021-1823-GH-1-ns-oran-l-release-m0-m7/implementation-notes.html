P0: preflight, branches, gate harness

  • decisionFork branches dev/l-release-nist180 cut from the upstream pins and pushed: Testbed 6088882 (+ L drop-in commit 03d71c0), ns-3 8c42089d, oran-interface 5f547ae, oran-e2sim 2209995.
  • deviationPins file is scripts/pins.conf, not scripts/pins.env. The local privacy hook blocks every *.env path and would prompt mid-run, breaking unattended runs. The file holds only public URLs and SHAs; same shell-sourceable format.
  • decisionGates run on the VM as transient systemd units (sudo systemd-run --uid=uc), launched by scripts/vm/vm-exec.sh. The wrapper writes exit_code last and the host polls for it, so an ssh drop never kills a gate and a crashed gate without a verdict is still detected.
  • decisionSnapshot overlays get explicit names /home/andang/VMs/ubuntu24.04-<snapshot>.qcow2 instead of libvirt's default <stem>.<snapshot>, so a revert-generated file can never collide with a later gate name.
  • decisionM0 is split into a host half (gate-m0-host.sh: host facts, visibility, anonymous clone, K4 snapshot probe, no VM credentials) and a VM half (gate-m0-preflight.sh). Each writes its own verdict.json; M0 is green only when both pass.
  • decisionThe evidence scrubber redacts every string from NIST's influxdb_auth_token.json plus any influx-v2-shaped token (80+ base64url chars ending ==). The regex deliberately cannot match 64-hex image digests or sha256 manifests.

  • decisionSnapshot semantics observed on libvirt 12.8 (K4 probe): reverting to the non-leaf fresh-install starts a new overlay with a generated name (ubuntu24.1792579224) on the raw base; sibling snapshots stay listed; deleting a leaf snapshot removes its overlay file. Overlays left behind by a revert are not deleted by libvirt, so the disk budget counts them.
